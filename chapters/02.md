# 2장. 계정·권한·비용 확인

## 학습 목표

1. Copilot Studio를 쓰기 전 확인할 계정·테넌트·역할·라이선스를 안다.
2. 평가 환경의 30일 만료와 자료 삭제 위험을 설명할 수 있다.
3. 접근이 안 될 때의 대체 계획을 세울 수 있다.

## 선행 개념

- 조직 계정: 회사가 발급한 Microsoft 365 계정. 개인 계정과 다르다.
- 테넌트: 회사의 Microsoft 365 전체 공간.
- 환경: 테넌트 안에서 데이터를 나누어 담는 공간 [S5].

## 쉬운 설명

Copilot Studio에서 무언가를 만들려면 먼저 들어갈 문이 있어야 한다. 문은 조직 계정이고, 방은 환경이다.

환경을 만들 때는 종류를 고른다. 연습용은 평가(Trial) 환경을 쓴다. 평가 환경은 30일이 지나면 만료되고, 안의 에이전트와 흐름과 자료가 모두 삭제된다 [S5]. 만료 2주 전부터 알림이 온다. 오래 쓸 것은 평가 환경에 두지 않는다.

환경 안에서 만들려면 Agent Author 역할이 필요하다 [S5]. 권한이 없으면 관리자에게 요청한다. "You do not have permissions to any environments"라는 오류가 뜨면 권한 문제다 [S5].

비용은 Copilot 크레딧으로 나간다. 미리보기 기능은 사양과 과금이 바뀔 수 있다. 실제 기능은 테넌트·권한·지역에 따라 다르게 보일 수 있다 [S2].

## 용어 풀이

- Agent Author: 환경 안에서 에이전트를 만들 수 있는 역할.
- Dataverse: 데이터를 저장하는 공간. 환경 만들 때 함께 만든다.
- 평가 환경 만료: 30일 후 환경과 안의 자료가 삭제되는 것.

## 가상 데이터 예시

가상의 두빛상사 IT 담당자가 신입 교육용 환경을 만든다고 가정한다.

- 계정: 조직 계정 (가상)
- 테넌트: 두빛상사 테넌트 (가상)
- 환경 종류: 평가 환경
- 주의: 30일 후 삭제되므로 교육 자료는 별도 보관

## 단계별 실습

실습 1. 환경 확인표와 접근 불가 시 대체 계획 작성

1. 아래 확인표의 각 항목에 대해 자신의 상태를 적는다. 모르면 미확인이라고 쓴다.
2. 접근 불가 항목이 하나라도 있으면 대체 계획을 적는다.
3. 대체 계획은 종이 설계 실습으로 정한다.

환경 확인표:

| 항목 | 확인할 것 | 내 상태 |
|------|----------|---------|
| 계정 | 조직 계정이 있는가 | |
| 테넌트 | 어느 테넌트에 속했는가 | |
| 역할 | Agent Author 역할이 있는가 | |
| 라이선스 | 필요한 라이선스가 있는가 | |
| 환경 | 평가/운영 중 무엇을 쓸 것인가 | |
| 만료일 | 평가 환경이라면 만료일은 언제인가 | |

## 복사용 프롬프트

Copilot Studio 사용 전 계정, 테넌트, 역할, 라이선스, 평가 환경 만료일을 점검할 표를 작성해줘.

## 예상 결과

여섯 항목이 모두 채워진 확인표와, 빈칸에 대한 대체 계획이 나온다.

## 흔한 오류와 해결책

- 오류: 평가 환경에 실제 업무 자료를 넣어 둔다. 해결: 만료 시 삭제되므로 [S5], 연습용 가상 자료만 둔다.
- 오류: 권한 오류를 프로그램 문제로 착각한다. 해결: 관리자에게 Agent Author 역할을 요청한다 [S5].

## 자가 점검표

- [ ] 확인표 6항목을 모두 채웠다
- [ ] 평가 환경 만료 위험을 설명할 수 있다
- [ ] 대체 계획을 적었다

## 계정 없는 독자를 위한 종이 설계 실습

위 실습 1을 종이에서 한다. 계정이 없어도 확인표 항목을 이해하고, 전부 미확인일 때의 대체 계획(종이 설계로 전 장 진행)을 적을 수 있다.
