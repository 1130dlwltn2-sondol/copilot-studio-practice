# 6장. AI 판단을 넣을 때의 한계

## 학습 목표

1. AI 판단과 규칙형 검증의 경계를 정할 수 있다.
2. 애매한 요청만 AI에게 맡기는 설계를 할 수 있다.
3. 불확실할 때 사람에게 넘기는 규칙을 만들 수 있다.

## 선행 개념

- 규칙형 검증: 정해진 기준과 비교하는 일. 빠르고 틀리지 않는다.
- AI 판단: 문맥을 읽고 분류·요약하는 일. 유연하지만 가끔 틀린다.
- 폴백: AI가 확신이 없을 때 사람에게 넘기는 것.

## 쉬운 설명

AI를 쓴다고 해서 모든 것을 AI에게 맡기면 안 된다. 금액 계산이나 날짜 비교는 규칙이 더 정확하다. AI는 애매한 문장을 분류하는 데 쓴다.

역할 나누기의 원칙은 다음과 같다.

| 작업 | 담당 | 이유 |
|------|------|------|
| 금액 합계 | 규칙 | 계산은 틀리면 안 된다 |
| 날짜 유효성 | 규칙 | 형식이 정해져 있다 |
| 품목 설명 분류 | AI | 표현이 다양하다 |
| 애매한 요청 | AI 후 사람 확인 | 판단이 필요하고 위험하다 |

AI에게 맡긴 작업에는 항상 확신도 기준을 둔다. 확신이 낮으면 사람에게 넘긴다. 이것이 폴백이다.

Hooks는 에이전트가 도구를 호출하기 전후에 정해진 로직을 실행하게 한다 [S1]. 예를 들어 도구 호출 전에 금액 범위를 검사하는 식이다. Hooks는 미리보기 상태다 [S1].

## 용어 풀이

- Hooks: 에이전트 실행 중 특정 시점에 정해진 로직을 끼워 넣는 기능. 미리보기 [S1].
- 결정적 제어: 매번 똑같이 실행되는 보장.

## 가상 데이터 예시

가상의 구매 요청 분류 (가상):

- REQ-001 노트북 2대: 금액 규칙 통과, 품목 명확 → 자동 처리
- REQ-004 "급하게 필요한 물품": 설명이 애매 → AI 분류 후 사람 확인
- REQ-005 금액 50,000,000원: 고액 → 규칙에서 걸러 승인자 전달

## 단계별 실습

실습 1. 애매한 요청만 AI에게 분류하도록 설계

1. 가상 요청 5개를 적는다. 명확한 것과 애매한 것을 섞는다.
2. 각 요청에 규칙/AI/사람 중 담당을 정한다.
3. AI 담당에는 확신도 기준과 폴백 조건을 적는다.
4. 아래 복사용 프롬프트로 AI에게 역할 나누기를 요청하고 비교한다.

## 복사용 프롬프트

금액·날짜는 규칙으로 처리하고 설명문 분류만 AI가 맡도록 역할을 나눠줘. 불확실하면 사람에게 넘겨줘.

## 예상 결과

작업별 담당(규칙/AI/사람)과 폴백 조건이 정리된 표가 나온다.

## 흔한 오류와 해결책

- 오류: AI에게 금액 계산을 맡긴다. 해결: 계산은 규칙으로 옮긴다.
- 오류: 폴백 없이 AI 결과를 그대로 쓴다. 해결: 확신도 기준과 사람 확인 단계를 넣는다.

## 자가 점검표

- [ ] 규칙/AI/사람 역할이 구분되었다
- [ ] 폴백 조건이 있다
- [ ] Hooks의 역할을 설명할 수 있다
