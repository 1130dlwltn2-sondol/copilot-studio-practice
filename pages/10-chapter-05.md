# 5장. 업무 앱 화면 구성

## 학습 목표

1. 업무 앱의 화면을 필드·검증·상태 표시로 정의할 수 있다.
2. 신청·검토·결과 3화면의 와이어프레임을 그릴 수 있다.
3. 미리보기 상태인 Apps의 제약을 알고 설계에 반영할 수 있다.

## 선행 개념

- 필드: 화면에서 입력받는 항목. 예: 품목명 입력칸.
- 검증: 입력값이 규칙에 맞는지 화면에서 바로 확인하는 것.
- 와이어프레임: 화면의 뼈대 그림. 네모와 선으로 그린다.

## 쉬운 설명

앱은 업무의 얼굴이다. Copilot Studio의 Apps는 자연어로 설명하면 초안을 만들어준다. "구매 요청 앱을 만들어줘. 입력 화면, 검토 화면, 결과 화면이 필요해"라고 적으면 된다 [S1].

화면을 설계할 때는 세 화면을 기본으로 한다.

1. 입력 화면: 요청자가 자료를 넣는다. 필드마다 입력 형식을 정한다.
2. 검토 화면: 승인자가 내용을 확인한다. 승인·반려 버튼이 있다.
3. 결과 화면: 처리 결과를 보여준다. 상태와 다음 행동이 보인다.

각 화면에는 다음을 정한다.

- 필드: 무엇을 입력받는가
- 검증: 빈칸·형식 오류를 어떻게 막는가
- 상태 표시: 진행 중·승인됨·반려됨을 어떻게 보여주는가

Apps는 2026년 10월 현재 공개 미리보기다 [S1]. 화면 구성은 바뀔 수 있으니, 설계는 종이 와이어프레임으로 먼저 확정한다.

## 용어 풀이

- Copilot Managed Runtime: 앱을 안전하게 실행하는 기반. 공개 미리보기 [S1].
- 플러그인 레지스트리: 재사용 가능한 기능을 모아둔 목록 [S1].

## 가상 데이터 예시

가상의 구매 요청 앱 3화면 (가상):

입력 화면: 품목명, 수량, 단가, 사유 입력칸. 금액은 자동 계산 표시.
검토 화면: 요청 내용 요약, 승인·반려 버튼, 의견 입력칸.
결과 화면: 승인 여부, 처리 번호, 다음 단계 안내.

## 단계별 실습

실습 1. 신청·검토·결과 3화면 와이어프레임 작성

1. 종이를 세 칸으로 나눈다.
2. 각 칸에 화면 이름을 적는다.
3. 네모로 입력칸과 버튼을 그리고 이름을 붙인다.
4. 각 화면의 검증 규칙을 옆에 적는다.
5. 아래 복사용 프롬프트로 AI에게 텍스트 와이어프레임을 요청하고 비교한다.

## 복사용 프롬프트

구매 요청 앱의 입력 화면, 검토 화면, 처리 결과 화면을 텍스트 와이어프레임으로 설계해줘.

## 예상 결과

세 화면의 구성 요소와 검증 규칙이 정리된 와이어프레임이 나온다.

## 흔한 오류와 해결책

- 오류: 화면이 너무 많다. 해결: 3화면으로 시작하고 필요할 때만 늘린다.
- 오류: 검증 없이 입력만 받는다. 해결: 필수값과 형식 검증을 화면마다 넣는다.

## 자가 점검표

- [ ] 3화면 와이어프레임이 있다
- [ ] 각 화면에 검증 규칙이 있다
- [ ] 미리보기 제약을 인지하였다
