# 4장. 자연어로 워크플로 설계

## 학습 목표

1. 반복되는 규칙형 작업을 문장으로 구조화할 수 있다.
2. 가상 CSV의 접수와 검증 단계를 명세서로 쓸 수 있다.
3. 자연어 흐름 제작의 한계를 알고 수동으로 보완할 수 있다.

## 선행 개념

- CSV: 쉼표로 구분된 표 형식의 텍스트 파일.
- 검증: 들어온 자료가 규칙에 맞는지 확인하는 일.
- 명세서: 무엇을 만들 것인지 적어 둔 문서.

## 쉬운 설명

에이전트 플로우는 자연어로 초안을 만들 수 있다 [S3]. "구매 요청 CSV가 오면 금액을 검증하고 오류는 보류해줘"라고 적으면 흐름의 뼈대가 생긴다. 하지만 AI가 만든 초안이 항상 맞는 것은 아니다. 사람이 명세서로 다듬어야 한다.

명세서에는 다음이 들어간다.

1. 입력: 어떤 자료가 들어오는가 (형식, 필수 항목)
2. 검증 규칙: 무엇을 확인하는가 (금액 범위, 필수값)
3. 분기: 통과와 실패 때 각각 무엇을 하는가
4. 출력: 결과가 어디에 기록되는가

가상의 구매요청 CSV 예시 (가상 자료):

```
요청번호,품목,수량,단가,요청자
REQ-001,노트북,2,1600000,김가상
REQ-002,마우스,5,30000,이가상
REQ-003,모니터,,450000,박가상
```

REQ-003은 수량이 비어 있다. 검증 단계에서 걸러져 보류되어야 한다.

## 용어 풀이

- 디자이너: 흐름을 눈으로 보고 편집하는 화면 [S3].
- 프롬프트 노드: 흐름 안에서 AI를 한 번 호출하는 단계.

## 단계별 실습

실습 1. 가상 CSV 접수와 검증 단계 설계

1. 위 가상 CSV를 종이에 옮겨 적는다.
2. 검증 규칙을 3개 이상 적는다. 예: 수량은 비어 있으면 안 된다.
3. 통과와 실패의 다음 단계를 각각 적는다.
4. 명세서 형식(입력·검증·분기·출력)으로 정리한다.
5. 아래 복사용 프롬프트로 AI에게 명세서를 요청하고 비교한다.

## 복사용 프롬프트

가상 구매요청 CSV를 받으면 금액과 필수 필드를 검증하고 오류 항목은 보류하는 워크플로 명세서를 작성해줘.

## 예상 결과

입력·검증·분기·출력이 정리된 명세서가 나온다. REQ-003 같은 오류 케이스가 보류 처리된다.

## 흔한 오류와 해결책

- 오류: 검증 규칙이 모호하다. 해결: 각 규칙에 통과 기준을 숫자로 적는다.
- 오류: 오류 항목을 그냥 버린다. 해결: 보류함에 넣고 사유를 기록한다.

## 자가 점검표

- [ ] 검증 규칙이 3개 이상이다
- [ ] 오류 항목의 처리가 정해져 있다
- [ ] 명세서 4요소가 갖춰졌다

## 계정 없는 독자를 위한 종이 설계 실습

위 실습 1을 종이에서 한다. CSV는 손으로 쓰고, 검증은 눈으로 하며, 명세서는 문서로 정리한다.
