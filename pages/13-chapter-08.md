# 8장. 완성 프로젝트: 구매요청 미니 시스템

## 학습 목표

1. 앱·흐름·승인·평가를 하나의 설계로 통합할 수 있다.
2. 구매요청 미니 시스템의 설계서와 테스트 보고서를 완성할 수 있다.
3. 앞 장의 산출물을 연결하여 재현 가능한 문서로 묶을 수 있다.

## 선행 개념

- 통합 설계: 따로 만든 부분을 하나로 묶는 것.
- 테스트 보고서: 테스트 결과와 판정을 정리한 문서.

## 쉬운 설명

1장부터 7장까지 만든 것을 하나로 묶는다. 각 장의 산출물은 다음 장에서 쓰였다. 8장에서는 전부 모아 미니 시스템 설계서를 만든다.

설계서의 구성은 다음과 같다.

1. 개요: 무엇을 만드는가
2. 앱 화면: 5장의 와이어프레임
3. 워크플로: 3~4장의 흐름도와 명세서
4. AI 예외 처리: 6장의 역할 나누기
5. 사람 승인: 5장의 검토 화면과 7장의 차단 조건
6. 테스트 케이스: 7장의 10건
7. 비용·권한 체크표: 2장의 확인표

테스트 보고서는 테스트 10건을 실행한 결과(가상 실행 또는 종이 검토)와 판정을 적는다.

## 단계별 실습

실습 1. 가상 구매 요청 미니 시스템 설계서와 테스트 보고서 완성

1. 1~7장의 산출물을 순서대로 펼친다.
2. 위 7개 항목의 틀에 각 산출물을 넣는다.
3. 빈 곳을 찾아 메운다.
4. 테스트 10건을 종이에서 실행해보고 결과를 적는다.
5. 아래 복사용 프롬프트로 AI에게 프로젝트 문서를 요청하고 비교한다.

## 복사용 프롬프트

앞선 결과를 모아 앱 화면, 워크플로, AI 예외 처리, 사람 승인, 테스트 케이스, 비용·권한 체크표를 포함한 프로젝트 문서를 만들어줘.

## 예상 결과

7개 항목이 채워진 설계서와 10건의 테스트 보고서가 나온다.

## 흔한 오류와 해결책

- 오류: 앞 장 산출물을 다시 만든다. 해결: 이미 만든 것을 가져다 쓴다.
- 오류: 테스트 보고서를 빼먹는다. 해결: 10건 중 1건이라도 실행 기록을 남긴다.

## 자가 점검표

- [ ] 설계서 7항목이 채워졌다
- [ ] 테스트 보고서가 있다
- [ ] 모든 산출물이 연결되었다

## 계정 없는 독자를 위한 종이 설계 실습

이 장 자체가 종이 설계의 완성이다. 계정 없이도 설계서 전체를 만들 수 있다.
